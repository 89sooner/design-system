# Conductor Design System 관측성 및 신뢰성

> 상태: review | 버전: v0.3 | 갱신일: 2026-07-17

## 1. 범위 재정의: 서비스 SLO가 아니라 파이프라인 관측성

Conductor Design System에는 가동 중인 서비스가 없으므로 요청 지연시간·에러율 같은 서비스 SLO/SLI는 존재하지 않는다(`../10_requirements/srs_final.md` 4.3 Out of Scope). 이 문서가 다루는 관측 대상은 세 가지다: (1) 빌드/CI 파이프라인의 신뢰성, (2) 문서 사이트 정적 호스팅의 가용성, (3) 소비자에게 전달되는 실패 신호(빌드 종료 코드, 콘솔 경고, 타입 오류). "장애"는 서버 다운타임이 아니라 파이프라인 실패 또는 배포 산출물의 결함이다.

## 2. 빌드/CI 신뢰성 지표

| 지표 | 목표 | 측정 방법 | 관련 요구사항 |
| --- | --- | --- | --- |
| `main` 브랜치 빌드 성공률(최근 30회 롤링) | 95% 이상 | CI 잡 결과 집계 | NFR-004 |
| CI 전체 소요 시간(p95) | 10분 이하 | CI 잡 실행 시간 로그 | NFR-004 |
| `pnpm build` 소요 시간(4코어) | 3분 이하 | CI 잡 소요 시간 | NFR-001 |
| 시각 회귀 검사 flake 비율(동일 커밋 재실행 시 결과 상이 비율) | 5% 이하 | JOB-CI-003 재실행 결과 비교 | R-2, OD-002 |
| 대비 검사 미달 쌍 검출 건수(릴리스 시점) | 0건 | `pnpm check:contrast` | NFR-003, FR-THM-004 |
| axe-core serious 이상 위반 검출 건수(릴리스 시점) | 0건 | `pnpm test:a11y` | NFR-003, FR-QA-003 |
| 번들 크기 초과 건수(`Button` 단독 import) | 0건, 4KB 이하 | `pnpm size` | NFR-001, FR-DX-003 |

시각 회귀 flake 비율이 5%를 초과하는 상태가 2회 연속 릴리스 사이클에서 관측되면, OD-002에 따라 JOB-CI-003을 필수 게이트에서 관찰 전용(모니터링만 하고 병합을 막지 않음)으로 전환하는 CR을 연다. 이는 R-2가 이미 식별한 완화 경로다.

## 3. 문서 사이트 가용성

| 지표 | 목표 | 측정 방법 |
| --- | --- | --- |
| 정적 호스팅 가용성(월간) | 99.9% 이상 | 5분 간격 합성 HTTP 확인(synthetic check)이 셸 화면(W-001)의 200 응답을 확인한다 |
| 배포 후 신규 버전 반영 지연 | 10분 이내 | 배포 잡 종료 시각과 합성 확인이 새 버전을 감지한 시각의 차이 |

문서 사이트는 서버 로직이 없으므로 가용성 저하의 원인은 호스팅 인프라 장애로 한정된다. 애플리케이션 코드 결함으로 인한 가용성 저하(예: JS 예외로 셸이 렌더되지 않는 경우)는 4절의 실패 신호로 별도 관리한다.

## 4. 소비자에게 노출되는 실패 신호

Conductor는 소비자의 빌드 파이프라인 내부에서 실행되므로, 실패 신호는 소비자의 빌드 로그와 개발자 콘솔에 나타난다.

| 신호 | 발생 조건 | 노출 위치 | 관련 요구사항 |
| --- | --- | --- | --- |
| 빌드 종료 코드 1 | 토큰 순환 참조, 대비 미달, 접두사 없는 커스텀 프로퍼티, 타입 생성 실패 등 | Conductor 자체 CI 로그(빌드 잡을 직접 실행하는 경우) | FR-TOK-003, FR-TOK-004, FR-THM-004 |
| TypeScript 컴파일 오류 | 존재하지 않는 토큰 키 접근, `IconButton`에 `aria-label` 누락 등 | 소비자의 `tsc` 실행 결과 | FR-TOK-006 AC-2, FR-CMP-002 AC-3 |
| 개발 빌드 콘솔 경고(1회) | `@conductor-by-89soone/css` 미import 상태에서 컴포넌트 렌더 | 소비자 브라우저 개발자 콘솔 | SCN-001 예외 흐름 |
| 개발 빌드 콘솔 경고 | 라벨 없는 `TextField`, `caption`/`aria-label` 없는 `Table`, 중첩 대화형 `Card`, 액션 슬롯 없는 위험 `Banner` | 소비자 브라우저 개발자 콘솔(프로덕션 빌드에서는 스트립) | FR-CMP-003, FR-CMP-005 AC-5, FR-CMP-007 AC-3, FR-CMP-008 AC-2 |
| `aria-live`/`aria-busy` 상태 전환 | 비동기 상태 변화(`loading` → 완료) | 보조기술(스크린리더) | FR-A11Y-005 AC-5 |

이 신호들은 Conductor가 통제할 수 있는 마지막 관측 지점이다. 소비자가 콘솔 경고를 무시하는 것은 Conductor의 관측 범위 밖이며, 문서 사이트 사용 규칙 페이지(W-040)에서 각 경고의 의미를 설명하는 것으로 책임 경계를 긋는다.

## 6. 알림 규칙

| Alert | 조건 | Severity | Runbook |
| --- | --- | --- | --- |
| ALERT-001 대비 검사 실패 | JOB-CI-001이 종료 코드 1 | High | 7.1 대비 검사 실패 런북 |
| ALERT-002 접근성 위반 검출 | JOB-CI-002가 serious 이상 위반 1건 이상 검출 | High | 7.2 axe 위반 런북 |
| ALERT-003 릴리스 배포 실패 | JOB-REL-001이 종료 코드 1 또는 부분 실패(3개 패키지 중 일부만 배포) | Critical | 7.3 배포 실패 런북 |
| ALERT-004 취약점 게이트 실패 | `pnpm audit --audit-level high`가 1건 이상 검출 | Critical | `conductor_security_privacy_architecture.md` 3.3 취약점 게이트 절차 |
| ALERT-005 Radix 업그레이드 파손 | JOB-CI-003 또는 수동 확인에서 Radix가 소유한 DOM 구조 변경으로 인한 시각 회귀 검출 | Medium | 7.4 Radix 업그레이드 파손 런북 |
| ALERT-006 시각 회귀 flake 임계 초과 | 2절의 flake 비율이 5%를 2회 연속 릴리스 사이클에서 초과 | Medium | OD-002에 따른 CR 개설 |

Critical은 릴리스를 즉시 차단하고 System Maintainer에게 통보한다. High는 해당 PR 병합을 차단한다. Medium은 다음 릴리스 계획 검토 항목으로 기록한다.

## 7. 런북

### 7.1 대비 검사 실패

1. 실패 리포트에서 위반 쌍 이름, 테마, 측정 대비율, 기준값을 확인한다: CI 아티팩트 또는 로컬 재현 `pnpm check:contrast --report`.
2. 위반 토큰이 본문 용도인지 장식 용도인지 판단한다.
   - 본문 용도라면: 프리미티브 값을 조정하고 `pnpm build`로 재생성한 뒤 `pnpm check:contrast`로 재검증한다.
   - 장식 용도라면: 토큰 메타데이터에 `usage: "decorative"`와 제외 사유 주석을 추가한다(FR-THM-004 예외 처리). 이 변경은 접근성 검토자 승인을 받는다.
3. `pnpm test:visual`을 실행해 값 조정이 다른 컴포넌트에 미친 시각 차이를 확인한다.
4. 수정을 커밋하고 PR을 재실행한다.

### 7.2 axe 위반 런북

1. 리포트에서 규칙 ID, 컴포넌트, 발생 상태(기본/hover 불가/disabled/오류/열림), 테마를 확인한다: `pnpm test:a11y --reporter=json`.
2. 위반이 실제 결함이면 해당 컴포넌트의 role/aria 속성 또는 마크업을 수정하고 로컬에서 `pnpm test:a11y -- --grep "<컴포넌트명>"`으로 재검증한다.
3. 위반이 오탐이면 규칙 ID와 사유를 허용 목록 파일에 기록하고, 접근성 검토자 승인을 받은 뒤 허용 목록을 W-050에서 조회 가능한 상태로 유지한다(FR-A11Y-005 예외 처리).
4. 두 테마 모두에서 재검증한다(FR-QA-003 AC-3).

### 7.3 배포 실패 런북

1. JOB-REL-001 로그에서 실패 단계를 확인한다(빌드 재실행 단계인지, `npm publish` 단계인지).
2. 3개 패키지 중 일부만 배포된 경우, 각 패키지의 현재 배포 버전을 확인한다.

   ```
   npm view @conductor-by-89soone/tokens version
   npm view @conductor-by-89soone/css version
   npm view @conductor-by-89soone/react version
   ```

3. 배포되지 않은 패키지가 있으면, 원인을 해결한 뒤 동일 태그로 재시도하지 않고 패치 버전을 새로 발행한다(태그 재사용은 provenance 기록의 일관성을 깨뜨린다).
4. 이미 배포된 패키지가 결함을 포함한 것으로 판명되면 `conductor_infrastructure_operations.md` 7절의 롤백 절차를 실행한다(목표 10분 이내).
5. 배포 실패 원인을 저장소 이슈에 기록하고 다음 릴리스 전 재발 방지 조치를 확인한다.

### 7.4 Radix 업그레이드 파손 런북

1. 시각 회귀 검사(JOB-CI-003) 또는 수동 확인에서 오버레이 컴포넌트(`Dialog`, `Drawer`, `Tooltip`, `DropdownMenu`)의 시각 차이를 확인한다.
2. Radix 패키지의 변경 이력에서 DOM 구조 변경(속성 이름 변경, 요소 계층 변경)을 확인한다.
3. Conductor CSS가 구조 셀렉터(`>`, `:nth-child`)를 사용하지 않는지 재확인한다(FR-CSS-004 AC-4). 구조 셀렉터가 있다면 이번 결함의 직접 원인이므로 `data-*` 속성 셀렉터로 교체한다.
4. `data-*` 속성 셀렉터만 사용했음에도 파손되었다면 Radix가 해당 속성 자체를 변경한 것이다. DEV를 등록하고(R-3), 새 속성 이름에 맞춰 CSS를 갱신한다.
5. Radix 버전을 정확한 신규 버전으로 고정(caret 미사용 유지)하고, `pnpm test:visual --update`로 기준 이미지를 갱신하기 전에 접근성 검토자가 변경 전후 시각 차이를 검토한다.
