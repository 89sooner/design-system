# Conductor Design System 화면 플로우 명세서

> 상태: review | 버전: v0.2 | 갱신일: 2026-07-10

## 1. 문서 위치와 책임

이 문서는 `conductor_product_ia.md`가 선언한 화면(W-001 ~ W-050) 사이의 전이를 정의한다. 범위를 추가하지 않는다. 모든 전이는 `../10_requirements/srs_final.md`의 FR을 근거로 인용한다.

이 문서가 소유하지 않는 것:

- 화면별 레이아웃, 섹션, 사용 컴포넌트 → `conductor_wireframe_spec.md`
- 상태별 필수 UI와 복구 경로 → `conductor_screen_state_matrix.md`
- 컴포넌트 계약 → `conductor_ui_component_spec.md`

## 2. 전이 모델의 전제

문서 사이트는 정적 빌드 산출물이며 서버 런타임이 없다(FR-DOC-001 AC-3). 실행 시 외부 도메인으로 네트워크 요청을 0건 발생시킨다(FR-DOC-001 AC-4). 따라서 이 제품의 전이 모델에는 다음이 존재하지 않는다.

| 존재하지 않는 것 | 근거 |
| --- | --- |
| 인증·세션·권한 확인 단계 | 런타임 인증/인가가 없다(SRS 6절) |
| `unauthenticated`, `no_permission`, `auth_expired` 전이 | 위와 같다 |
| 서버 응답 실패에 따른 전이 | 런타임 데이터 요청이 없다(FR-DOC-001 AC-4) |
| `offline` 전이 | 실행 시 네트워크 요청이 없으므로 연결 상태가 화면 전이에 영향을 주지 않는다 |
| 낙관적 갱신, 재시도 큐, 부분 실패 롤백 | 쓰기 연산이 없다 |

남는 전이는 세 종류다. (1) 라우트 이동, (2) 오버레이 개폐, (3) 화면 내 상태 전이(테마, 필터, 복사).

## 3. 전이 공통 규칙

1. 전이는 사용자의 현재 컨텍스트를 보존한다. 라우트 이동 시 선택된 테마는 유지된다(FR-DOC-005 AC-2).
2. 실패 전이는 원인, 영향, 복구 경로를 화면에 표시한다. 실패를 콘솔에만 남기지 않는다.
3. 라우트 이동 후 포커스는 새 화면의 `<main id="content">`로 이동한다. 이동하지 않으면 키보드 사용자가 이전 화면의 내비 항목에 남는다(FR-A11Y-002 AC-1).
4. 라우트 이동은 브라우저 히스토리 항목을 하나 추가한다.
5. 오버레이 개폐, 테마 전환, 토큰 필터는 히스토리 항목을 추가하지 않는다. 근거는 4절과 5절에 있다.

## 4. 오버레이 규칙

Conductor의 오버레이는 `Dialog`(C-040), `Drawer`(C-041), `Tooltip`(C-042), `DropdownMenu`(C-043) 네 종류다. 모두 Radix UI 프리미티브 위에 구현된다(FR-CMP-006). 전체화면(full-screen) 전이는 이 제품에 존재하지 않는다. 문서 사이트의 모든 화면은 셸 안에서 렌더되기 때문이다(FR-DOC-001 AC-2).

| 규칙 | 내용 | 근거 |
| --- | --- | --- |
| 포커스 트랩 | `Dialog`와 `Drawer`가 열린 동안 포커스가 오버레이 내부에 갇힌다 | FR-CMP-006 AC-1 |
| Escape 닫기 | Escape가 오버레이를 닫고 포커스를 트리거로 되돌린다 | FR-CMP-006 AC-1, FR-A11Y-002 AC-3 |
| 배경 스크롤 잠금 | `Dialog`와 `Drawer`가 열린 동안 배경 스크롤이 잠긴다 | FR-CMP-006 AC-2 |
| 겹침 순서 | 오버레이는 `z.overlay`(40)와 `z.popover`(50) 토큰을 사용한다 | FR-CMP-006 AC-4, FR-TOK-008 AC-1 |
| 자체 구현 금지 | 포커스 트랩, 롤 관리, 키보드 내비게이션을 Conductor가 자체 구현한 건수가 0건이다 | FR-CMP-006 AC-5, ADR-004 |
| 히스토리 | 오버레이는 히스토리 항목을 만들지 않는다 | 아래 결정 참조 |

**결정: 오버레이는 브라우저 히스토리를 소유하지 않는다.** 오버레이가 히스토리 항목을 만들면 뒤로가기가 "화면 이동 취소"와 "오버레이 닫기" 중 무엇인지 사용자가 예측할 수 없고, 두 동작이 같은 키에 겹친다. Escape가 이탈 경로를 항상 제공하므로(FR-A11Y-002 예외/실패 처리) 뒤로가기를 이탈 경로로 중복 배정할 이유가 없다. 오버레이가 열린 상태에서 뒤로가기를 누르면 오버레이가 닫히고 이전 화면으로 이동한다. 이 순서는 라우트 변경 시 열린 오버레이를 언마운트하는 규칙(9절 FLOW-005 참조)으로 보장된다.

## 5. 딥링크 규칙

정적 빌드가 모든 화면 경로를 사전 생성한다. `/components/:componentId`의 라우트 인스턴스는 컴포넌트 메타데이터(`ENT-CMP-001`)에서 전수 생성되므로, 산출물에 존재하는 `componentId` 집합은 `@conductor/react` 공개 export 집합과 같다(FR-DOC-003 AC-5).

| 진입 대상 | 동작 |
| --- | --- |
| 산출물에 존재하는 경로 | 해당 화면이 셸 안에서 렌더된다. 중간 화면을 거치지 않는다 |
| 산출물에 없는 경로 | 정적 호스팅이 `404.html`을 반환한다. `404.html`은 셸 안에서 W-020의 `not_found` 상태를 렌더하고, 요청된 경로 문자열과 카탈로그 복귀 경로를 표시한다 |

**결정: 존재하지 않는 경로는 새 화면 ID를 갖지 않는다.** `404.html`에 별도 화면 ID를 부여하면 FR 근거 없는 화면이 생긴다. W-020의 `not_found` 상태로 표현하면, 사용자는 찾던 컴포넌트가 없다는 사실과 존재하는 컴포넌트 전수를 같은 화면에서 확인한다.

이 제품에는 런타임 권한이 없으므로 딥링크의 `no_permission`, `auth_expired` 분기가 존재하지 않는다. 딥링크 진입 시 로그인 화면으로의 리다이렉트도 존재하지 않는다.

## 6. 뒤로가기 규칙

| 상황 | 뒤로가기 동작 |
| --- | --- |
| 라우트 이동 후 | 이전 화면으로 이동한다. 선택된 테마는 유지된다 |
| 오버레이가 열린 상태 | 오버레이가 언마운트되고 이전 화면으로 이동한다. 오버레이 자체를 닫는 데는 Escape 또는 닫기 버튼을 사용한다 |
| 오프캔버스 내비가 열린 상태 | 내비가 닫히고 이전 화면으로 이동한다 |
| 테마 전환 후 | 테마는 되돌아가지 않는다. 테마 전환은 히스토리 항목이 아니다 |
| 토큰 필터 입력 후 | 필터는 되돌아가지 않는다. 필터 문자열은 히스토리 항목이 아니다 |
| W-021 딥링크 직접 진입 후 | 히스토리에 이전 항목이 없으면 브라우저가 문서 사이트를 벗어난다. W-021 헤더의 W-020 복귀 링크가 사이트 내부 복귀 경로를 항상 제공한다 |

**결정: 테마와 필터는 URL 상태가 아니다.** 테마는 브라우저에 유지되는 사용자 선택이고(FR-DOC-005 AC-2) 필터는 화면 내 임시 조회 조건이다(FR-DOC-004 AC-1). 두 값을 URL에 실으면 공유된 링크가 수신자의 테마 선택과 시스템 설정을 덮어써 FR-DOC-005 AC-3을 위반한다.

## FLOW-001 문서 탐색 (셸 → 카탈로그 → 컴포넌트 상세)

관련 요구사항: FR-DOC-001, FR-DOC-003, FR-CMP-002 ~ FR-CMP-008, FR-CMP-009 AC-4

### 트리거

사용자가 문서 사이트에 진입한다. 진입 경로는 직접 URL, 사이드 내비, 본문 링크 중 하나다.

### 단계별 전이

| 단계 | 화면 | 동작 | 결과 |
| --- | --- | --- | --- |
| 1 | — | 사용자가 `/`로 진입한다 | 셸이 렌더되고 W-001이 `<main id="content">`에 렌더된다(FR-DOC-001 AC-2) |
| 2 | W-001 | skip-link에 포커스한 뒤 활성화한다(선택) | 포커스가 `<main id="content">`로 이동한다(FR-CMP-009 AC-4) |
| 3 | W-001 | 사이드 내비의 `Components` 선택 (`nav.select`) | W-020으로 이동. 히스토리 항목 +1 |
| 4 | W-020 | 카탈로그가 컴포넌트군 8개로 렌더된다 | 각 카드가 축소 프리뷰를 실제 DOM으로 마운트한다(FR-DOC-003 AC-1) |
| 5 | W-020 | 컴포넌트 카드 클릭 또는 Enter (`component.open`) | `/components/:componentId`(W-021)로 이동. 히스토리 항목 +1 |
| 6 | W-021 | 라이브 프리뷰, props 표, 사용 규칙, 코드 스니펫이 렌더된다 | 프리뷰가 모든 `variant`와 `tone` 조합을 렌더하고 현재 테마를 따른다(FR-DOC-003 AC-3, AC-4) |

### 성공 경로

`/` → W-001 → W-020 → W-021. 각 단계에서 포커스가 새 화면의 본문으로 이동하고, Tab 순서가 시각 순서와 일치한다(FR-A11Y-002 AC-1).

### 실패 경로

| 실패 | 감지 | 처리 |
| --- | --- | --- |
| W-020의 축소 프리뷰 한 개가 렌더 중 예외를 던진다 | 오류 경계 | 해당 카드만 `partial_failure`로 격리하고 나머지 카탈로그를 계속 렌더한다(FR-DOC-003 예외/실패 처리). 전이는 중단되지 않는다 |
| W-021의 라이브 프리뷰가 렌더 중 예외를 던진다 | 오류 경계 | 해당 프리뷰 영역만 `Banner tone="danger"`로 대체한다. props 표, 스니펫, 사용 규칙은 계속 렌더된다 |
| 카탈로그에 없는 컴포넌트가 공개 export에 존재한다 | 빌드 | 빌드가 실패한다(FR-DOC-003 AC-5). 이 실패는 런타임 전이가 아니라 배포 차단이다 |

### 예외 흐름

- **딥링크로 W-021에 직접 진입한다.** 1 ~ 5단계를 거치지 않는다. 헤더의 W-020 복귀 링크가 카탈로그로의 경로를 제공한다.
- **존재하지 않는 `componentId`로 진입한다.** 5절 딥링크 규칙에 따라 `404.html`이 W-020의 `not_found` 상태를 렌더한다. 복구 경로는 카탈로그 목록 자체다.

### 오버레이 규칙

이 플로우는 오버레이를 열지 않는다. W-021의 오버레이 컴포넌트 프리뷰를 조작하면 FLOW-004로 진입한다.

### 딥링크

`/components/:componentId`로 직접 진입하면 W-021이 즉시 렌더된다. 인증 확인, 리다이렉트, 중간 로딩 화면이 없다. `componentId` 목록은 W-021 사양의 30행 표를 참조한다.

### 뒤로가기

W-021에서 뒤로가기는 W-020으로 이동한다. W-020에서 뒤로가기는 W-001로 이동한다. 딥링크로 W-021에 직접 진입한 경우 히스토리에 이전 항목이 없으므로 뒤로가기가 사이트를 벗어난다.

## FLOW-002 테마 전환

관련 요구사항: FR-DOC-005, FR-THM-003, FR-THM-001, FR-THM-002

### 트리거

사용자가 상단바의 테마 토글(C-054 Switch)을 조작한다. 토글은 `role="switch"` 또는 `aria-pressed`를 노출하고 키보드로 조작 가능하다(FR-DOC-005 AC-5).

### 단계별 전이

| 단계 | 화면 | 동작 | 결과 |
| --- | --- | --- | --- |
| 1 | W-001 ~ W-050 (전 화면) | 토글 조작 (`theme.toggle`) | 루트 요소의 `data-cdt-theme` 값이 `dark` ↔ `light`로 바뀐다(FR-DOC-005 AC-1) |
| 2 | 동일 화면 | 테마 팔레트가 적용된다 | CSS 커스텀 프로퍼티 값만 바뀌며 컴포넌트가 재마운트되지 않는다(FR-THM-003 AC-4) |
| 3 | 동일 화면 | 선택이 브라우저에 유지된다 | 새로고침 후에도 마지막 선택이 유지된다(FR-DOC-005 AC-2) |
| 4 | 동일 화면 | 재페인트가 완료된다 | 100ms 이하(NFR-001) |

화면 이동이 발생하지 않는다. 히스토리 항목이 추가되지 않는다(6절 결정 참조).

### 성공 경로

토글 조작 → `data-cdt-theme` 변경 → 팔레트 교체 → 선택 유지. `data-cdt-theme` 속성이 존재하면 `prefers-color-scheme`을 무시한다(FR-THM-003).

### 실패 경로

| 실패 | 감지 | 처리 |
| --- | --- | --- |
| `localStorage` 접근이 차단되었다 (프라이빗 모드) | 저장 시도의 예외 | 예외를 삼키고 `prefers-color-scheme`으로 대체한다. 저장 실패가 화면 렌더를 막지 않는다(FR-DOC-005 예외/실패 처리). 현재 세션의 테마 선택은 유지되며 새로고침 시 시스템 설정으로 돌아간다 |
| `data-cdt-theme` 값이 `dark`/`light` 이외다 | 테마 결정 로직 | 다크 팔레트를 적용한다(FR-THM-003 AC-3) |
| 라이트 팔레트에만 없는 semantic 키가 존재한다 | 토큰 계약 테스트 | `pnpm test`가 실패하고 누락 키를 테마별로 출력한다(FR-QA-001 AC-1). 이 실패는 런타임 전이가 아니라 배포 차단이다 |

### 예외 흐름: 최초 페인트의 테마 깜빡임 방지

FR-THM-003의 예외 처리와 FR-DOC-005 AC-4가 이 흐름을 규정한다. 최초 페인트 시 테마가 뒤바뀌어 보이는 깜빡임이 발생하지 않아야 한다.

| 단계 | 시점 | 동작 |
| --- | --- | --- |
| 1 | 서버 렌더 / 정적 HTML 생성 | 루트 요소에 `data-cdt-theme`를 쓰지 않는다. 빌드 시점에는 사용자의 저장된 선택과 시스템 설정을 알 수 없다 |
| 2 | `<head>` 파싱 | `<head>`에 인라인으로 삽입된 테마 결정 스니펫이 동기 실행되어 루트에 `data-cdt-theme`를 설정한다 |
| 3 | 최초 페인트 | 루트 속성이 이미 확정되었으므로 첫 픽셀이 최종 테마로 그려진다 |
| 4 | hydration | React가 루트 속성을 덮어쓰지 않는다. 서버와 클라이언트의 첫 렌더 결과가 일치해 hydration 경고가 0건이다(FR-DX-004 AC-3) |

스니펫의 결정 순서는 저장된 선택 → `prefers-color-scheme` → 다크다(FR-DOC-005 AC-3, FR-THM-003 AC-2, AC-3).

스니펫은 `@conductor/css`가 자동 주입하지 않는다. 패키지가 자동 주입하면 모듈 최상위에서 `document`와 `localStorage`에 접근하게 되어 FR-DX-004를 위반한다. 소비자가 `<head>`에 직접 삽입하며, 삽입 가능한 스니펫 소스는 W-002가 제공한다(FR-THM-003 예외/실패 처리).

스니펫을 삽입하지 않은 소비자는 최초 페인트에서 다크 팔레트를 보고, hydration 이후 저장된 선택으로 전환된다. 이 결과와 삽입 방법을 W-002가 `Banner tone="warning"`으로 명시한다.

### 오버레이 규칙

테마 전환은 오버레이를 열거나 닫지 않는다. 오버레이가 열린 상태에서 토글을 조작할 수는 없다. 포커스가 오버레이 내부에 갇혀 있어 상단바 토글에 도달하지 못하기 때문이다(FR-CMP-006 AC-1). 이는 의도된 결과이며 우회 경로를 만들지 않는다.

### 딥링크

테마는 URL에 실리지 않는다(6절 결정 참조). 어떤 화면의 딥링크로 진입하든 테마 결정 순서는 동일하다.

### 뒤로가기

테마 전환은 히스토리 항목을 만들지 않으므로 뒤로가기가 테마를 되돌리지 않는다. 되돌리려면 토글을 다시 조작한다.

## FLOW-004 오버레이 열기/닫기 및 포커스 복귀

관련 요구사항: FR-CMP-006, FR-A11Y-002 AC-3, FR-TOK-008

### 트리거

사용자가 W-021의 오버레이 컴포넌트 프리뷰(`dialog`, `drawer`, `tooltip`, `dropdown-menu`) 또는 W-040의 `Dialog`/`Drawer` 선택 기준 섹션에서 트리거를 조작한다.

### 단계별 전이

| 단계 | 화면 | 동작 | 결과 |
| --- | --- | --- | --- |
| 1 | W-021 / W-040 | 트리거에 포커스가 있다 | 포커스 링이 `--cdt-focus-ring` 토큰의 시각 표시를 받는다(FR-A11Y-001) |
| 2 | 동일 화면 | Enter, Space, 또는 클릭 (`overlay.open`) | 오버레이가 열린다. 라우트는 바뀌지 않는다 |
| 3 | 동일 화면 | 오버레이가 열린 동안 | 포커스가 오버레이 내부에 갇힌다(FR-CMP-006 AC-1). 배경 스크롤이 잠긴다(AC-2). `z.overlay`(40) 또는 `z.popover`(50)로 셸 위에 렌더된다(AC-4) |
| 4 | 동일 화면 | Escape 또는 닫기 버튼 (`overlay.close`) | 오버레이가 닫힌다 |
| 5 | 동일 화면 | 닫힌 직후 | **포커스가 2단계의 트리거 요소로 복귀한다**(FR-CMP-006 AC-1, FR-A11Y-002 AC-3). 배경 스크롤 잠금이 해제된다 |

포커스 복귀는 이 플로우의 핵심 수용 기준이다. FR-A11Y-002 AC-3은 `Dialog`, `Drawer`, `DropdownMenu`, `Select` 네 컴포넌트에서 Escape가 오버레이를 닫고 포커스를 트리거로 되돌릴 것을 요구한다. `Select`(C-053)는 폼 컴포넌트군에 속하지만 열림 상태에서 오버레이와 동일한 포커스 규칙을 따른다.

포커스 트랩, 롤 관리, 키보드 내비게이션, 포커스 복귀는 Radix UI에 위임한다. Conductor가 자체 구현한 건수가 0건이다(FR-CMP-006 AC-5, ADR-004). 따라서 이 플로우의 구현은 Radix 프리미티브를 올바르게 조립하는 일이며, 복귀 로직을 새로 작성하는 일이 아니다.

### 성공 경로

트리거 포커스 → 열기 → 내부 포커스 트랩 → Escape → 닫기 → 트리거로 포커스 복귀. 사용자가 키보드에서 손을 떼지 않고 이전 위치로 돌아온다.

### 실패 경로

| 실패 | 감지 | 처리 |
| --- | --- | --- |
| 닫은 뒤 포커스가 `<body>`로 떨어진다 | 키보드 경로 테스트(FR-A11Y-002 AC-5) | 테스트가 실패하고 CI가 차단한다. 트리거 요소가 언마운트되지 않도록 프리뷰 구조를 고친다 |
| 오버레이 내부에서 Tab이 배경으로 새어 나간다 | 키보드 경로 테스트 | 테스트가 실패한다. Radix 프리미티브를 우회한 커스텀 포커스 처리를 제거한다(FR-CMP-006 AC-5) |
| 오버레이가 닫힌 상태인데 키보드 트랩이 남는다 | FR-A11Y-002 AC-2 | 테스트가 실패한다. 오버레이 내부의 의도된 트랩만 AC-2의 예외다 |
| Radix 버전 업그레이드로 DOM 구조가 바뀐다 | 시각 회귀 또는 수동 확인 | `data-*` 속성 셀렉터만 사용하므로 스타일이 유지된다. 구조 변경이 감지되면 `DEV-###`를 등록한다(FR-CMP-006 예외/실패 처리) |

### 예외 흐름

- **오버레이 내부에서 이탈 경로가 필요하다.** Escape 또는 닫기 버튼이 항상 이탈 경로를 제공한다(FR-A11Y-002 예외/실패 처리). 두 경로 중 하나라도 없는 오버레이를 렌더하지 않는다.
- **포커스 링이 부모의 `overflow: hidden`에 잘린다.** 해당 컴포넌트에 `z-index` 상승 규칙을 적용한다(FR-A11Y-001 예외/실패 처리).
- **트리거가 오버레이 닫힘과 동시에 언마운트된다.** 이 제품의 프리뷰에서는 발생하지 않는다. 프리뷰의 트리거는 오버레이 개폐와 무관하게 상시 렌더된다.

### 오버레이 규칙

4절이 규정한다. `Tooltip`(C-042)은 포커스와 hover 양쪽에서 열리고 Escape로 닫힌다(FR-CMP-006 AC-3). `Tooltip`은 포커스를 트랩하지 않으며 배경 스크롤을 잠그지 않는다. 포커스는 트리거에 머무르므로 별도의 복귀 단계가 없다.

### 딥링크

오버레이는 URL을 갖지 않는다. 딥링크로 열린 오버레이 상태를 재현할 수 없으며, 재현 경로를 제공하지 않는다. 오버레이는 화면이 아니라 화면 내 상태이기 때문이다.

### 뒤로가기

오버레이가 열린 상태에서 뒤로가기를 누르면 오버레이가 언마운트되고 이전 화면으로 이동한다(6절). 뒤로가기가 오버레이만 닫고 화면에 머무르지 않는다. 오버레이를 닫고 같은 화면에 머무르려면 Escape를 사용한다.

## FLOW-005 모바일 오프캔버스 내비

관련 요구사항: FR-CMP-009 AC-3, FR-CMP-009 AC-4, FR-CSS-003 AC-2, FR-CSS-003 AC-3

### 트리거

뷰포트 폭이 800px(**breakpoint.md**) 미만이다. 사이드 내비가 오프캔버스로 전환되고 상단바에 내비 열기 버튼(C-002 IconButton)이 나타난다.

FR-CMP-009는 우선순위 Should이며 OD-004가 열려 있다. OD-004의 결정과 무관하게 이 플로우는 성립한다. 셸이 `@conductor/react`에 있든 문서 사이트 내부에 있든, 문서 사이트의 오프캔버스 동작은 동일하다.

### 단계별 전이

| 단계 | 화면 | 동작 | 결과 |
| --- | --- | --- | --- |
| 1 | 전 화면 | 뷰포트가 800px 미만으로 좁아진다 | 사이드 내비가 오프캔버스로 전환된다(FR-CMP-009 AC-3). 본문이 단일 컬럼이 된다(FR-CSS-003 AC-2) |
| 2 | 전 화면 | 내비 열기 버튼 조작 (`nav.open`) | `Drawer`(C-041)가 열리고 `NavList`(C-071)를 렌더한다. 포커스가 드로어 내부에 갇힌다(FR-CMP-006 AC-1). 배경 스크롤이 잠긴다(AC-2). `z.drawer`(30)로 렌더된다 |
| 3 | 전 화면 | 내비 항목 선택 (`nav.select`) | 라우트가 이동하고 드로어가 언마운트된다. 포커스가 새 화면의 `<main id="content">`로 이동한다 |
| 4 | 뷰포트 560px 미만 | 추가 전환 | `cdt-card-grid`가 단일 컬럼으로 전환된다(FR-CSS-003 AC-3). 폼 컨트롤 최소 높이가 40px에서 42px로 증가한다(FR-CMP-007 AC-5) |

### 성공 경로

내비 열기 → 항목 선택 → 라우트 이동 → 드로어 자동 닫힘 → 새 화면 본문에 포커스.

**결정: 라우트가 이동하면 오프캔버스 내비를 닫는다.** 드로어를 열어둔 채 라우트만 바꾸면, 새 화면의 본문이 드로어 뒤에 가려진 채 배경 스크롤이 잠긴 상태로 남는다. 사용자는 자신이 이동했다는 사실을 관찰할 수 없다.

### 실패 경로

| 실패 | 감지 | 처리 |
| --- | --- | --- |
| 드로어를 닫지 않고 라우트가 이동한다 | 키보드 경로 테스트 | 배경 스크롤 잠금이 남아 본문을 스크롤할 수 없다. 라우트 변경 시 드로어를 언마운트한다(위 결정) |
| 드로어가 닫힌 뒤 포커스가 `<body>`로 떨어진다 | FR-A11Y-002 AC-2 | 항목 선택으로 닫힌 경우 포커스는 새 화면 본문으로 이동한다. Escape로 닫힌 경우 포커스는 내비 열기 버튼으로 복귀한다 |
| 800px 이상에서 오프캔버스가 남는다 | 뷰포트 리사이즈 | 뷰포트가 800px 이상이 되면 드로어를 언마운트하고 사이드 내비를 고정 렌더한다. 배경 스크롤 잠금을 해제한다 |

### 예외 흐름

- **오버레이 클릭 또는 Escape로 닫는다.** 라우트를 이동하지 않고 드로어만 닫는다. 포커스가 내비 열기 버튼으로 복귀한다(FR-CMP-009 AC-3, FR-A11Y-002 AC-3).
- **드로어가 열린 상태에서 뷰포트가 800px 이상으로 넓어진다.** 드로어를 언마운트하고 사이드 내비를 고정 렌더한다. 포커스가 언마운트된 요소에 남지 않도록 내비 열기 버튼이 사라지기 전에 포커스를 `<main id="content">`로 옮긴다.
- **skip-link를 사용한다.** 오프캔버스 상태에서도 skip-link는 셸의 첫 포커스 대상이며 본문 영역으로 포커스를 이동시킨다(FR-CMP-009 AC-4).

### 오버레이 규칙

오프캔버스 내비는 `Drawer`(C-041)로 구현되므로 4절의 오버레이 규칙을 전부 따른다. 포커스 트랩, Escape 닫기, 배경 스크롤 잠금, `z.drawer` 토큰 사용이 적용된다. 추가 규칙은 오버레이 클릭으로도 닫힌다는 것이다(FR-CMP-009 AC-3).

### 딥링크

오프캔버스 내비의 열림 상태는 URL을 갖지 않는다. 어떤 화면의 딥링크로 진입하든 내비는 닫힌 상태로 시작한다.

### 뒤로가기

드로어가 열린 상태에서 뒤로가기를 누르면 드로어가 언마운트되고 이전 화면으로 이동한다(6절). 드로어만 닫으려면 Escape 또는 오버레이 클릭을 사용한다.

## FLOW-006 코드 스니펫 복사

관련 요구사항: FR-DOC-006, FR-A11Y-005 AC-5

### 트리거

사용자가 W-021의 코드 스니펫 섹션, 또는 W-002·W-012의 `CodeBlock`(C-032) 옆 복사 버튼(C-002 IconButton)을 누른다.

### 단계별 전이

| 단계 | 화면 | 동작 | 결과 |
| --- | --- | --- | --- |
| 1 | W-021 / W-002 / W-012 | 복사 버튼에 포커스가 있다 | 포커스 링이 표시된다(FR-A11Y-001) |
| 2 | 동일 화면 | Enter, Space, 또는 클릭 (`snippet.copy`) | 예제 소스 코드를 클립보드에 기록한다 |
| 3 | 동일 화면 | 기록 성공 | 2초 이내에 `복사됨` 상태가 표시된다(FR-DOC-006 AC-1) |
| 4 | 동일 화면 | 상태 알림 | 복사 완료가 `aria-live="polite"` 영역으로 알려진다(FR-DOC-006 AC-2). 비동기 상태 변화가 보조기술에 전달된다(FR-A11Y-005 AC-5) |
| 5 | 동일 화면 | 2초 경과 | 버튼이 원래 상태로 복귀한다(FR-DOC-006 AC-1) |

라우트가 바뀌지 않는다. 히스토리 항목이 추가되지 않는다. 포커스는 복사 버튼에 머무른다.

### 성공 경로

버튼 조작 → 클립보드 기록 → `복사됨` 표시 → `aria-live` 알림 → 2초 후 복귀.

### 실패 경로: 클립보드 미지원 폴백

FR-DOC-006 AC-3과 예외/실패 처리가 두 가지 실패를 구분한다. 두 실패 모두 오류 배너를 띄우지 않는다. 배너는 사용자의 시선을 코드 블록에서 떼어 놓지만, 사용자가 원하는 것은 코드를 얻는 일이기 때문이다.

| 실패 | 감지 시점 | 처리 |
| --- | --- | --- |
| Clipboard API를 사용할 수 없다 | 렌더 시점 | 복사 버튼을 `disabled`로 렌더한다. 코드 블록의 텍스트가 선택 가능한 상태로 유지되어 사용자가 직접 선택해 복사한다(FR-DOC-006 AC-3). 화면 상태는 `copy_unavailable` |
| 클립보드 쓰기가 거부되었다 (권한 거부) | 조작 시점 | 오류 배너를 표시하지 않고 버튼에 `복사할 수 없음` 상태를 표시한다(FR-DOC-006 예외/실패 처리). 코드 블록 텍스트는 선택 가능한 상태로 유지된다 |

두 경우 모두 `CodeBlock`이 가로 스크롤을 제공하고 모노스페이스 폰트로 렌더한다(FR-CMP-005 AC-4). 텍스트가 잘려 선택할 수 없는 상태가 되지 않는다.

Clipboard API 사용 가능 여부는 모듈 최상위가 아니라 `useEffect` 또는 이벤트 핸들러 내부에서 확인한다(FR-DX-004 AC-2). 서버 렌더 시 복사 버튼은 활성 상태로 렌더되고, hydration 이후 미지원 환경에서만 `disabled`로 전환된다. 이 전환은 서버와 클라이언트의 첫 렌더 결과를 일치시켜 hydration 경고 0건을 유지한다(FR-DX-004 AC-3).

### 예외 흐름

- **2초 안에 복사 버튼을 다시 누른다.** 복귀 타이머를 재시작하고 `복사됨` 상태를 유지한다. `aria-live` 영역은 같은 문자열을 다시 알리지 않는다. 중복 알림은 스크린리더 사용자에게 소음이 된다.
- **복사 버튼이 `disabled`인데 키보드로 도달한다.** `disabled` 버튼은 포커스를 받지 않는다. 사용자는 코드 블록 텍스트에 도달해 직접 선택한다.
- **`prefers-reduced-motion: reduce`가 설정되어 있다.** `복사됨` 상태 전환의 지속 시간 계산값이 `0s`가 되지만 최종 시각 결과는 동일하다(FR-CSS-005 AC-1, AC-2). 2초 복귀 타이머는 애니메이션이 아니라 상태 유지 시간이므로 감소 모드에서도 유지된다.

### 오버레이 규칙

이 플로우는 오버레이를 열지 않는다. `복사됨` 상태는 토스트가 아니라 버튼 자신의 상태다. 토스트/스낵바는 제공하지 않으며 알림 큐 관리는 소비자 책임이다(FR-CMP-008 예외/실패 처리).

### 딥링크

복사 상태는 URL을 갖지 않는다. 딥링크로 W-021에 진입하면 복사 버튼은 항상 기본 상태로 시작한다.

### 뒤로가기

복사는 히스토리 항목을 만들지 않으므로 뒤로가기가 복사를 되돌리지 않는다. 클립보드 내용은 브라우저와 운영체제가 소유하며 문서 사이트가 관여하지 않는다.
