# Conductor Design System 화면 상태 매트릭스

> 상태: review | 버전: v0.3 | 갱신일: 2026-07-15

## 1. 목적과 범위

이 문서는 `srs_final.md`와 `requirements_screen_traceability_matrix.md`가 승인한 요구사항을 화면 상태로 번역한다. 이 문서는 범위를 추가하지 않는다. 화면 ID는 `requirements_screen_traceability_matrix.md` 3절의 W-001 ~ W-050 체계를 그대로 사용하며, D-###/A### 체계는 Conductor에 존재하지 않는다.

Conductor는 3개 npm 패키지와 1개 정적 문서 사이트를 배포하며, 문서 사이트가 유일한 사용자 인터페이스다. 런타임 인증·인가·서버가 없다(SRS 6절 권한 경계, 5.3 보안/운영 제약). 이 사실은 2절과 3절의 여러 항목을 `해당 없음`으로 처리하는 근거이며, 임의 판단이 아니라 SRS에 명시된 제품 경계에서 도출된다.

## 2. 공통 상태 분류 체계

| 상태 | 정의 | 이 제품 적용 여부 |
| --- | --- | --- |
| loading_initial | 화면이 최초로 표시되기 전까지의 구간 | 적용. 3.1절 참조 |
| empty | 조회 결과가 0건인 상태 | 적용. 3.1절 참조 |
| stale | 표시된 데이터의 최신성이 낮아지는 상태 | 해당 없음: 문서 사이트는 릴리스마다 전체 재빌드되는 정적 산출물이다(FR-DOC-001 AC-3). 세션 중 시간 경과에 따라 낮아지는 데이터가 없다. 배포 후 브라우저가 이전 캐시를 표시하는 문제는 배포 파이프라인의 캐시 무효화 책임이며 화면 상태가 아니다 |
| no_permission | 사용자 권한 부족으로 접근이 차단되는 상태 | 해당 없음: 이 제품에는 런타임 인증/인가가 없다(SRS 6절). 소비자 개발자 권한은 저장소 접근 권한과 릴리스 승인 권한으로 구현되며, 문서 사이트 자체에는 로그인이나 권한 게이트가 없다 |
| auth_expired | 인증 세션이 만료된 상태 | 해당 없음: no_permission과 동일한 근거. 문서 사이트에는 세션 개념이 없다 |
| offline | 네트워크 연결이 끊긴 상태 | 해당 없음: 배포 산출물은 실행 시 네트워크 요청을 발생시키지 않는다(NFR-002, 5.3 보안/운영 제약 1). 최초 페이지 로드 자체의 네트워크 실패는 브라우저 표준 오프라인 화면이 처리하며 제품이 정의하는 화면 상태가 아니다 |
| partial_failure | 화면 구성 요소 중 일부만 실패한 상태 | 적용. 3.1절 참조 |
| recoverable_error | 재시도 또는 대체 경로로 복구 가능한 오류 | 적용. 3.1절 참조 |
| unrecoverable_error | 사용자가 화면에서 이탈해야 하는 복구 불가 오류 | 해당 없음: 정적 산출물은 요청마다 동일한 초기 상태에서 출발하므로 새로고침이 곧 복구 경로다. 사용자가 영구적으로 이탈해야 하는 화면을 정의하지 않는다. 빌드 자체가 실패하면(FR-TOK-003 AC-3, FR-TOK-006 예외처리) 산출물이 배포되지 않으므로 이는 SFC-CLI/SFC-CI 표면의 상태이며 실행 중인 문서 사이트 화면에는 도달하지 않는다 |
| operation_pending | 사용자 조작에 대한 처리가 진행 중인 상태 | 적용. 3.1절 참조 |

## 3. 이 제품 고유 상태

### 3.1 정의

공통 분류 중 적용 대상인 5종(loading_initial, empty, partial_failure, recoverable_error, operation_pending)은 아래 5개의 제품 고유 상태로 구체화된다. 각 상태는 어느 공통 분류를 구체화하는지 표기한다.

| 고유 상태 | 구체화하는 공통 분류 | 정의 | 발생 근거(FR) |
| --- | --- | --- | --- |
| 대비 검사 결과 파일 없음 | partial_failure | `pnpm check:contrast`가 실행되지 않아 대비율 측정 결과 파일이 없는 상태. 토큰 값 자체는 표시되지만 대비율 열만 비어 있다 | FR-DOC-004 예외처리 |
| 프리뷰 렌더 실패 | partial_failure | 컴포넌트 라이브 프리뷰 마운트 중 예외가 발생한 상태. 오류 경계가 해당 프리뷰 영역만 격리한다 | FR-DOC-003 예외처리 |
| 클립보드 미지원 | recoverable_error의 완화형(사용자 개입 없이 자동으로 기능이 축소된다) | 브라우저 환경에 Clipboard API가 없는 상태. 복사 버튼이 처음부터 비활성으로 렌더된다 | FR-DOC-006 AC-3 |
| localStorage 차단 | recoverable_error의 완화형(사용자 개입 없이 자동으로 대체값이 적용된다) | 프라이빗 모드 등에서 `localStorage` 접근이 차단되어 테마 선택을 저장할 수 없는 상태 | FR-DOC-005 예외처리 |
| 감소 모션 활성 | 공통 10종 어디에도 속하지 않는 별도 유형(사용자 환경설정 반영 상태) | OS의 `prefers-reduced-motion: reduce` 설정이 켜진 상태. 오류가 아니라 사용자 환경설정을 그대로 반영한 정상 상태다 | FR-CSS-005 |

`클립보드 미지원`과 `클립보드 쓰기 거부`는 서로 다른 상태다. 전자는 API 자체가 없어 버튼이 처음부터 `disabled`로 렌더되는 상태(FR-DOC-006 AC-3)이고, 후자는 API는 있으나 쓰기 호출이 거부되어 버튼에 `복사할 수 없음`이 표시되는 상태(FR-DOC-006 예외처리)다. 후자는 별도의 고유 상태로 분리하지 않고 공통 분류의 `recoverable_error` 그대로 4.2절에서 다룬다.

| partial_failure / 프리뷰 렌더 실패 | 특정 규칙의 예시 컴포넌트 마운트 중 예외가 발생할 때 | 해당 예시 영역만 오류 경계로 격리되고 나머지 규칙은 계속 렌더된다 | 페이지 새로고침으로 재시도 |

#### W-050 Accessibility

| 상태 | 발생 조건 | 화면 표현 | 복구 경로 |
| --- | --- | --- | --- |
| loading_initial | 화면 최초 페인트 구간 | 대비 검사·axe 허용 목록·키보드 도달 안내가 확정된 내용으로 표시된다 | 자동 완료 |

## 5. 컴포넌트 수준 상태와 화면 상태의 관계

FR-CMP-001 ~ FR-CMP-009가 정의하는 컴포넌트 상태(disabled, loading, error, selected)는 4절의 화면 상태와 다른 층위에 있다. 컴포넌트 상태는 W-021의 프리뷰 안에서 하나의 variant/tone 조합으로 나타나는 정상 렌더 결과이고, 화면 상태는 화면 자체가 데이터를 얻거나 렌더링에 성공했는지를 나타낸다. 둘은 독립적으로 조합된다.

| 컴포넌트 상태 | 정의하는 FR | 화면 상태와의 관계 |
| --- | --- | --- |
| disabled | FR-CMP-002 AC-4(버튼), FR-CMP-007(폼 컨트롤 최소 높이·상태) | 화면이 `loading_initial` 없이 정상 렌더된 뒤에도 개별 컴포넌트 인스턴스가 `disabled`일 수 있다. W-021의 props 표와 프리뷰가 `disabled` variant를 별도 조합으로 렌더한다(FR-DOC-003 AC-3). 정책상 차단된 버튼은 `disabled`와 함께 차단 사유를 `title` 또는 `aria-describedby`로 노출한다(FR-CMP-002 AC-5) |
| loading | FR-CMP-002 AC-2(`aria-busy`), FR-CMP-008 AC-5(`Spinner`/`ProgressRing`) | 화면의 `loading_initial`(화면이 아직 표시되지 않음)과 컴포넌트의 `loading`(화면은 표시되었고, 그 안의 한 컴포넌트 인스턴스가 진행 중 상태를 보여주는 예시)은 서로 다르다. `감소 모션 활성` 상태에서는 `Spinner`/`ProgressRing`의 `loading` 표현이 애니메이션 대신 정적 진행률 텍스트로 바뀐다(FR-CSS-005 예외처리) — 화면 고유 상태가 컴포넌트 상태의 표현 방식을 바꾸는 유일한 사례다 |
| error | FR-CMP-007 AC-2(`aria-invalid`), FR-CMP-008 AC-1(`Banner tone="danger"`) | 컴포넌트의 `error` variant는 정상적으로 렌더된 오류 상태의 예시이며, 화면의 `partial_failure`/`프리뷰 렌더 실패`(렌더 자체가 실패해 오류 경계로 격리됨)와는 배타적이다. 전자는 "오류를 성공적으로 표시함", 후자는 "표시 자체에 실패함"이다 |
| selected | FR-CMP-003 AC-2(대화형 `Card`), FR-CMP-005 AC-3(`Timeline` 단계) | 화면 상태 목록에 없으며 사용자 상호작용 결과로 나타난다. `empty`(W-030 필터 0건)와 동시에 발생할 수 없지만, `loading_initial` 이후 어느 시점에도 나타날 수 있다 |

W-001과 W-021의 뷰포트 800px 미만 오프캔버스 내비게이션(FR-CMP-009 AC-3, OD-004 조건부)은 화면 상태가 아니라 `NavList`/`AppShell`의 열림/닫힘 컴포넌트 상태다. 이 상태는 4절 매트릭스에 포함하지 않는다.

## 6. 복구 경로 표

| 상태 | 사용자 행동 | 결과 |
| --- | --- | --- |
| loading_initial | 대기(추가 조작 불필요) | 최초 페인트가 완료되고 확정된 테마·값으로 콘텐츠가 표시된다 |
| empty(W-030 필터 0건) | 필터 조건 수정 또는 필터 초기화 | 조건에 맞는 토큰 행이 다시 표시된다 |
| partial_failure / 프리뷰 렌더 실패 | 페이지 새로고침으로 재시도 | 격리되었던 프리뷰 영역이 재마운트를 시도한다. 반복 실패 시 컴포넌트 소스 수정이 필요하다 |
| recoverable_error(클립보드 쓰기 거부) | 브라우저 클립보드 권한 재설정 후 재시도, 또는 코드 텍스트를 직접 선택해 복사 | 복사 동작이 완료되거나 수동 복사로 대체된다 |
| operation_pending(코드 복사) | 대기(2초 이내) | 복사 버튼이 원래 상태로 복귀한다 |
| operation_pending(테마 리페인트) | 대기(100ms 이내, NFR-001) | 선택한 테마의 토큰 값으로 재페인트가 완료된다 |
| 대비 검사 결과 파일 없음 | `pnpm check:contrast` 실행 | 대비율 수치와 pass/fail 판정이 채워지고 경고 배너가 사라진다 |
| 클립보드 미지원 | 코드 블록 텍스트를 직접 드래그로 선택해 복사 | 복사 버튼 없이도 코드를 얻으며, 버튼은 계속 `disabled`로 유지된다 |
| localStorage 차단 | 없음(자동으로 `prefers-color-scheme`이 적용된다) | 세션 내 테마는 OS 설정을 따르며 화면 렌더는 막히지 않는다 |
| 감소 모션 활성 | OS 접근성 설정에서 "동작 줄이기" 해제(선택 사항) | 해제하면 전환/애니메이션이 복원된다. 유지하면 정적 진행률 텍스트가 계속 표시된다 |
